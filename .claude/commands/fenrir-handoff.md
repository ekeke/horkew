# Fenrir ハンドオフ文書生成

セッション終了時に、次のセッション（自分または別のClaude）が即座に作業を再開できるように引き継ぎ文書を作成する。

## Step 1: 情報収集（並列で実行）

以下を収集:

1. **学習状況**: 最新の `progress.md` と `eval_log.jsonl`
2. **git 差分**: `git log --oneline` で今日のコミットを列挙、`git diff --stat` で未コミットの変更
3. **未完了タスク**: `tasks/todo.md` の残り項目
4. **実行中のジョブ**: checkpoint-base パス、コマンドライン引数

## Step 2: ハンドオフ文書の作成

`tasks/training-handoff-{YYYY-MM-DD}.md` に以下の構成で書き出す:

```markdown
# Fenrir 学習セッション引き継ぎ ({日付})

## 今日やったこと
- 変更の概要（箇条書き、ファイルパス付き）
- 重要なバグ修正や設計変更は詳細に記述

## 現在の学習状況
- Phase, checkpoint-base, iter 数
- eval 推移（テーブル）
- baseline と卒業ラインの値

## 懸念事項
- 学習曲線の異常や未解決の問題
- バグ修正前に開始されたジョブの注意

## 推奨: 次のステップ
- 番号付きリストで優先順位順に

## コマンドまとめ
- 学習の開始/再開コマンド
- スナップショット生成コマンド

## アーキテクチャ概要（変更があった場合のみ）
- 新しいデータフローや設計変更の図

## ファイル構成（今回の変更）
- 変更ファイルのテーブル

## off-by-one 注意（該当があれば）
- インデックスのずれなど、次のセッションでハマりそうな罠
```

## Step 3: lessons.md の更新

セッション中にユーザーから修正を受けた場合、`tasks/lessons.md` に追記:

```markdown
## {日付}: {教訓のタイトル}
- **状況**: 何をしていたか
- **問題**: 何が間違っていたか
- **学び**: 次回どうするか
```

## Step 4: memory の更新

セッション中に得た以下の情報を auto memory に保存:

- **feedback**: ユーザーからの修正や好み
- **project**: 学習フェーズの進捗、設計上の決定事項
- **reference**: 新しいファイルやツールの所在

## 注意事項

- ハンドオフ文書はコードから導出できる情報（ファイル構成、関数シグネチャ等）は最小限に
- **なぜその設計にしたか**、**何が上手くいかなかったか**を重点的に記述
- 実行中のジョブのコマンドラインは正確に記録する（再現性のため）
