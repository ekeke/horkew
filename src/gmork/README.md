# Gmork

役職否定理由の言語化ライブラリ。

Retarが「何が可能か」をビットマスクで計算するのに対し、Gmorkは「なぜその役職が不可能なのか」を人間向けテキストで説明する。Retarとは独立した軽量チェッカーとして動作し、特定の仮説（席X＝役職Y）を検証して最初に見つかった矛盾を返す。

## 入力・出力

```typescript
import { explain } from './index.ts'

const reason = explain(villageStatus, setup, seat, role)
// => "2d夜: 単独襲撃死のため人狼ではありえない" など
```

| パラメータ | 型 | 説明 |
|---|---|---|
| `village` | `VillageStatus` | 村の状態（Retarと同じ） |
| `setup` | `Map<SystemRole, number>` | 配役（Retarと同じ） |
| `seat` | `Seat` (number) | 対象の席番号 |
| `role` | `SystemRole` | 否定された役職 |

否定理由を説明する日本語文字列を返す。理由が特定できない場合は `'わかりません'` を返す。

---

## 否定理由カタログ

### 1. 死因による否定

ゲーム中の死亡イベントから直接導かれる制約。観測事実なので仮説に依存しない。

#### 1.1 単独夜襲撃死 → 人狼ではない

夜にその席だけが死亡した場合、人狼の襲撃先なので人狼本人ではありえない。

- **条件**: `causeOfDeath` が夜死亡系 かつ その夜の死者が1人だけ
- **否定**: `werewolf`
- **例**: 「2d夜: 単独襲撃死のため人狼ではありえない」

> 複数人が同じ夜に死亡した場合は、護衛失敗・呪殺・猫又道連れなどの可能性があるため、この制約は適用されない。

#### 1.2 呪殺道連れ死 → 人狼に確定

猫又が夜に殺された場合、道連れで死亡した席は人狼である。（猫又の呪いは人狼にのみ発動する）

- **条件**: `causeOfDeath === 'cursed_by_killed_nekomata'`
- **否定**: `werewolf` 以外のすべて
- **例**: 「猫又の呪殺道連れにより人狼確定」

#### 1.3 処刑猫又の呪殺死 → 人狼に確定

猫又が処刑された場合、同日に呪殺死した席は人狼である。

- **条件**: `causeOfDeath === 'cursed_by_executed_nekomata'`
- **否定**: `werewolf` 以外のすべて

#### 1.4 背徳後追い死 → 背徳者に確定

妖狐が処刑・襲撃・呪殺で死亡した際に後追い死した席は背徳者である。

- **条件**: `causeOfDeath === 'follow_executed_hamster'` または `'follow_killed_hamster'`
- **否定**: `immoralist` 以外のすべて
- **例**: 「妖狐死亡による後追い死のため背徳者確定」

### 2. CO（カミングアウト）による否定

プレイヤーの宣言行動から導かれる制約。

#### 2.1 村人CO → 村役職ではない

村人COした席は特殊な村役職（占い・霊媒・狩人・共有・猫又）を持たない。真の村役職なら村人COはしないという前提。

- **条件**: `claimingRole === 'villager'`
- **否定**: `seer`, `medium`, `bodyguard`, `mason`, `nekomata`
- **例**: 「村人COしているため占い師ではありえない」

#### 2.2 降参CO → 村陣営ではない

降参COした席は人外（人狼・狂人・狂信者・妖狐・背徳者）のいずれかである。

- **条件**: `claimingRole === 'surrender'`
- **否定**: `villager`, `seer`, `medium`, `bodyguard`, `mason`, `nekomata`

#### 2.3 無言処刑 → 村役職ではない

COせずに処刑された席は特殊な村役職ではない。真の村役職なら処刑前にCOするという前提。

- **条件**: 処刑死 かつ `claiming === false`
- **否定**: `seer`, `medium`, `bodyguard`, `mason`, `nekomata`
- **例**: 「COなしで処刑されたため霊媒師ではありえない」

> この制約には「COすべきだったのにしなかった」という推定が含まれる。Retarではオプション（`claimingDueDate`）で制御される。

### 3. 占い結果による否定

占い師のCO者がいる場合、その結果から導かれる制約。占い師が真であるという仮定のもとで成立する。

#### 3.1 白判定 → 人狼ではない

占い師が対象を「白（人間）」と判定した場合、対象は人狼ではない。

- **条件**: 占いCO者の `assertions` に `{ target: seat, species: 'human' }` がある
- **否定**: `werewolf`
- **例**: 「占い師Aの2d白判定により人狼ではない」

> 妖狐は占い結果が白になるため、白判定だけでは妖狐を否定できない。

#### 3.2 黒判定 → 人狼に確定

占い師が対象を「黒（人狼）」と判定した場合、対象は人狼である。

- **条件**: 占いCO者の `assertions` に `{ target: seat, species: 'wolf' }` がある
- **否定**: `werewolf` 以外のすべて
- **例**: 「占い師Aの3d黒判定により人狼確定」

#### 3.3 呪殺の発生 → 占い先は妖狐

占い師が占った夜に妖狐が死亡（呪殺）した場合、その占い先が妖狐だったと推定できる。このとき占い師は呪殺日まで生存している必要がある。

- **条件**: 占い師の占い先が呪殺で死亡 かつ 占い師がその日まで生存
- **否定**: 占い先の `werehamster` 以外を否定（妖狐確定）

### 4. 霊媒結果による否定

霊媒師のCO者がいる場合、処刑された席の霊媒結果から導かれる制約。霊媒師が真であるという仮定のもとで成立する。

#### 4.1 白判定 → 人狼ではない

霊媒師が処刑者を「白」と判定した場合、処刑者は人狼ではない。

- **条件**: 霊媒CO者の `assertions` に `{ target: seat, species: 'human' }` がある
- **否定**: `werewolf`
- **例**: 「霊媒師Bの白判定により人狼ではない」

#### 4.2 黒判定 → 人狼に確定

霊媒師が処刑者を「黒」と判定した場合、処刑者は人狼である。

- **条件**: 霊媒CO者の `assertions` に `{ target: seat, species: 'wolf' }` がある
- **否定**: `werewolf` 以外のすべて

### 5. 共有結果による否定

共有者は互いの存在を認識できる。共有者COの相互確認から導かれる制約。

#### 5.1 共有相方認定 → 共有者に確定

共有者が相方として認定した席は共有者である。

- **条件**: 共有CO者の `assertions` に `{ target: seat, species: 'human' }` がある
- **否定**: `mason` 以外のすべて（対象席）
- **例**: 「共有者Cの相方認定により共有者確定」

#### 5.2 共有者は黒判定を出さない

共有者の能力は相方の確認のみであり、黒判定（人狼認定）を出すことはない。共有CO者が黒判定を出した場合、その仮説自体が矛盾する。

### 6. 役職枠の制約

配役（setup）で定められた各役職の人数から導かれる制約。

#### 6.1 CO者数が枠を超過 → 偽CO者が存在

ある役職に対してCO者数が配役枠を上回る場合、超過分は偽者（人外）である。

- **例**: 占い師枠1に対し3人がCO → 少なくとも2人は偽者

#### 6.2 枠が全てCO者で埋まっている → 非CO者はその役職ではない

ある役職の枠数とCO者数が一致し、かつ対象席がCO者でない場合、対象席はその役職ではない。

- **条件**: `setup.get(role) === claimants.length` かつ対象席が非CO者
- **否定**: 当該役職
- **例**: 「占い師枠1に対しAがCO済みのため、占い師ではありえない」

> ただしCO者の中に偽者が含まれる可能性があるため、単純に枠＝CO者数だけでは否定できない場合がある。偽者の存在余地（人外枠）も考慮が必要。

#### 6.3 配役に存在しない → その役職ではない

配役に含まれていない役職（枠が0）はそもそも存在しない。

- **条件**: `setup.get(role) === 0` または `setup.has(role) === false`
- **否定**: 当該役職

### 7. 人外枠（偽者予算）の制約

配役に含まれる人外役職（人狼・狂人・狂信者・妖狐・背徳者）の合計数が「偽者予算」となる。この予算を超えて偽COが発生することはできない。

#### 7.1 偽者数超過 → 仮説が矛盾

対象席を当該役職と仮定した場合、必要な偽者数が人外枠の合計を超えてしまうならその仮定は成立しない。

- **条件**: 仮定の結果、必要な偽者数 > 人外役職の合計枠
- **否定**: 当該役職
- **例**: 「この席が村人だと仮定すると、占い師CO者3人のうち偽者が3人必要だが、人外枠は2人しかない」

#### 7.2 非CO村役職は追加偽者としてカウント

配役上存在するがCOしていない村役職（潜伏役職）がいる場合、その分だけ追加の偽者カウントが必要になる（真役職がCOしていないため、CO者のどれかが枠を消費していない）。

### 8. 猫又固有の制約

#### 8.1 猫又の夜死亡には道連れが必要

猫又が夜に死亡する場合、必ず人狼1人を道連れにする。その夜に単独で死亡している場合は猫又ではない。

- **条件**: 夜死亡 かつ その夜の死者が1人だけ
- **否定**: `nekomata`（対象席について）
- **例**: 「夜の死者が1人のため、猫又ではありえない（道連れがいない）」

#### 8.2 猫又処刑時の呪殺 → 死亡者は人狼

猫又が処刑された場合、ランダムに人狼1人を呪殺する。処刑日に呪殺死した席は人狼である（1.3と同じ）。

### 9. 妖狐固有の制約

#### 9.1 妖狐は占い師に占われると死亡（呪殺）

占い師が妖狐を占った夜、妖狐は死亡する。この死亡が通常の襲撃死と同じ夜に発生すると、複数人が夜に死亡する現象が起こる。

#### 9.2 妖狐が全滅している場合 → それ以降の死者・生存者は背徳者ではない

妖狐が全員死亡した後に死亡した席、および妖狐全滅後も生存している席は背徳者ではない。（背徳者は妖狐が死亡した時点で後追い死するため）

- **条件**: 全妖狐が死亡済み かつ 対象席が妖狐死亡後も生存 or 妖狐死亡後に死亡
- **否定**: `immoralist`
- **例**: 「妖狐が2dに全滅しているが、この席は3dまで生存していたため背徳者ではない」

### 10. 背徳者固有の制約

#### 10.1 背徳者は妖狐が死亡すると後追い死する

妖狐が存在しない配役では背徳者も存在しえない。また妖狐の死亡タイミングと背徳者の後追い死タイミングが一致する必要がある。

- **条件**: `setup.get('werehamster') === 0` かつ `role === 'immoralist'`
- **否定**: `immoralist`

### 11. 夜死亡数の整合性

各夜の死亡者数は、ゲームメカニクスと整合する必要がある。

#### 11.1 基本: 毎夜1人が襲撃死

人狼は毎夜1人を襲撃する。追加の死亡（呪殺・猫又道連れ・背徳後追い）がない限り、夜死亡者は1人。

#### 11.2 死亡数過多 → 追加死因が必要

夜の死者が期待値（1＋追加死因分）を超える場合、背徳者の後追い死や猫又道連れなどで説明できる必要がある。説明できなければ仮説が矛盾。

#### 11.3 死亡数過少 → 護衛成功 or 妖狐襲撃

夜の死者が0人の場合、狩人の護衛成功か妖狐への襲撃で説明できる必要がある。このとき狩人または妖狐がまだ可能な席が存在しなければ仮説が矛盾。

### 12. 勝敗結果による制約

ゲームの勝敗が確定している場合、最終盤面の役職分布が勝利条件と整合する必要がある。

#### 12.1 村勝利 → 人狼全滅

村陣営勝利の場合、最終的に生存している人狼は0人。

- **否定**: 生存席の `werewolf`（生存者が人狼であることを否定）

#### 12.2 狼勝利 → 人狼が生存者の過半数以上

人狼陣営勝利の場合、生存人狼数 ≧ 生存村人数。

#### 12.3 狐勝利 → 妖狐が生存

妖狐勝利の場合、最低1匹の妖狐が生存している。

## 推論の難易度分類

### Tier 1: 直接推論（単一の観測事実から導出）

1つの事実だけで結論が出る。実装が容易。

- 死因による確定（1.1〜1.4）
- COによる否定（2.1〜2.3）
- 配役不在（6.3）
- 妖狐不在→背徳不在（10.1）

### Tier 2: 単純な組み合わせ推論（2〜3の事実の組み合わせ）

少数の事実を組み合わせて導出。比較的実装しやすい。

- 占い/霊媒結果による否定（3.1〜4.2）※どの占い師/霊媒師を信じるかの選択を含む
- 共有相方の確認（5.1）
- 枠の充足（6.1, 6.2）
- 猫又の道連れ不在（8.1）
- 妖狐全滅後の背徳否定（9.2）

### Tier 3: 連鎖推論（複数の制約が連鎖的に絡む）

仮説を立てて矛盾を導く必要がある。実装の複雑度が高い。

- 偽者予算の超過（7.1, 7.2）※複数のCO者×複数の役職枠の計算
- 夜死亡数の整合性（11.1〜11.3）
- 勝敗結果との整合（12.1〜12.3）

### Tier 4: 全探索由来（Retarのバックトラッキングでのみ検出可能）

Gmorkでは原理的に検出が難しい、または計算コストが高い推論。

- 複数の役職仮説が同時に矛盾する場合
- ソルバーの制約伝播で初めて判明する否定（J.3, J.4）
- 組み合わせ爆発が発生するケース

これらについては `'わかりません'` を返す。

## 設計方針

- Retarとは独立した軽量チェッカーとして動作する
- 内部で構造化データ（`DenialReason` discriminated union）を生成し、フォーマッター関数で日本語文字列に変換する
- Tier 1 → Tier 2 → Tier 3 の順に段階的に実装する
- 検出できない否定理由には `'わかりません'` を返す
- 現時点ではスタブ実装（常に `'わかりません'` を返す）
